Q01ProjectEasy

What is Folio, and what problem does it solve?

View answer+

Folio is a collaborative whiteboard for students and teams. It brings drawings, text, pictures, and notes into one shared workspace. A group can discuss an idea, annotate a diagram, and present its work without switching between several applications.

Q02ProjectEasy

What are the main features of your project?

View answer+

The main features are drawing tools, editable text and sticky notes, image uploads and annotations, live collaboration, and up to 20 pages per workspace. It also supports undo/redo for local object edits, page presentation, PNG export, and printing pages as a PDF.

Q03ProjectEasy

Which technologies did you use in Folio?

View answer+

The frontend uses React, Vite, and Canvas 2D. The backend uses Node.js, Express, and Socket.IO. MongoDB Atlas stores workspace data, images, accounts, and sessions. The frontend and backend are hosted together on Azure App Service.

Q04CanvasMedium

How does drawing work on the whiteboard?

View answer+

The editor handles pointer events and converts pointer positions into canvas coordinates. A pen stroke is stored as an object containing points, color, size, and an ID. Canvas 2D renders those objects, which lets the application redraw a saved page instead of storing only a screenshot.

Q05CanvasMedium

How does the eraser remove writing without erasing the uploaded image?

View answer+

Reference images and annotations are rendered separately. The image is drawn on the base layer, while annotations are drawn on an offscreen ink canvas. The eraser removes pixels from the ink canvas using destination-out, leaving the reference image underneath unchanged.

Q06CanvasMedium

Why does the project use a fixed 1600 × 900 canvas?

View answer+

A fixed logical size gives every device the same coordinate system. The board is displayed at a suitable size for the screen, and pointer positions are converted back into the 1600 × 900 space. This keeps drawings in the same place when a phone and a laptop open the same workspace.

Q07CollaborationMedium

How can two users see changes in the same workspace?

View answer+

Socket.IO connects the browsers to the server. Users in the same workspace join a room identified by its board ID. When a completed edit is validated and saved, the server broadcasts the updated studio state to that room. Other workspaces have separate rooms.

Q08CollaborationEasy

Where is the whiteboard data saved, and what happens after a refresh?

View answer+

Workspace pages and their drawing objects are saved in MongoDB Atlas. Image data is stored separately from the page objects. After a refresh or a new join, the server sends the current studio state and the browser renders the saved objects again.

Q09CollaborationMedium

What happens if the internet disconnects while a user is editing?

View answer+

For an already loaded workspace, pending edits are kept in a local queue and saved to localStorage when available. After reconnecting, the client loads the latest server state and sends the remaining edits. Recent action IDs help avoid duplicate saves. If another user changed the same object, a version check can reject the conflicting edit.

Q10SecurityMedium

How does the sign-in and login process work?

View answer+

A user registers with a name, email, and password. After successful registration or login, the server issues a random session token in an HttpOnly cookie. The database stores a hash of that token and its expiry. The server checks the session for protected image routes and live connections; logout revokes the session and disconnects its sockets.

Q11SecurityEasy

How are users’ passwords protected?

View answer+

Passwords are stored as salted scrypt hashes rather than plaintext. A random salt makes the stored hashes different even when two users choose the same password. During login, the submitted password is hashed with the stored salt and compared with the saved result.

Q12SecurityEasy

How does image upload work in this project?

View answer+

The browser accepts PNG, JPEG, or WebP images, resizes them, and compresses them before upload. The server checks the type, file signature, size, and workspace upload limit before saving the bytes in MongoDB. The uploaded image is added as a locked reference object that can be annotated.

Q13DeploymentEasy

How did you deploy Folio?

View answer+

Folio is hosted on Azure App Service using the F1 Free plan, with MongoDB Atlas as its database. Express serves the built React frontend, API routes, and Socket.IO connection from one HTTPS origin. Database credentials are supplied through Azure application settings and are not committed to GitHub.

Q14DeploymentMedium

How did you test that the application works correctly?

View answer+

The project uses Vitest for unit and integration tests, including drawing validation, page limits, edit conflicts, authentication, and Socket.IO collaboration. The reviewed release passed 114 server tests and 22 client tests. Browser checks also verified image uploads, saved pages after reload, and live changes between two tabs.

Q15DeploymentEasy

What are the current limitations and possible future improvements?

View answer+

The current release allows signed-in users with a workspace link to collaborate, but it does not have private-board roles or password recovery. Undo history is local to the current tab session, and the free hosting plan is intended for a small demonstration. Future improvements could include workspace permissions, account recovery, and better support for larger groups.
