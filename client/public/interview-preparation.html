Q01Project

Tell me about your project in about one minute.

Reveal sample answer+

Folio is a collaborative visual workspace for students and teams. People can draw, write text, upload a picture and annotate it, organize up to 20 pages, and present the pages as slides. React provides the interface, Canvas 2D renders the workspace, Socket.IO carries live updates, and MongoDB Atlas stores the data. The account-enabled version runs on one Azure website.

Q07Canvas

Why use a 1600 × 900 logical canvas? How do pointer coordinates stay correct?

Reveal sample answer+

All clients store coordinates in the same logical board space even when their screen sizes differ. The canvas is fitted and zoomed visually. Pointer coordinates are converted using the displayed canvas rectangle: x = (clientX − left) / displayedWidth × 1600, with the equivalent calculation for y and 900. The displayed rectangle already reflects the current positioning and scale.

Q08Canvas

How can the eraser remove annotations without damaging the uploaded picture?

Reveal sample answer+

The renderer separates base-layer reference images from ink-layer annotations. It paints the base objects first, draws the ink onto a separate offscreen canvas, and then composites that ink onto the main surface. The eraser uses destination-out on the ink surface. It therefore removes annotation pixels while leaving the reference image underneath intact.

Q09Canvas

How is a pen stroke represented, and why not save a screenshot after every movement?

Reveal sample answer+

A stroke is a vector object with an ID, tool, style, and an array of logical points. Pen input can also include pressure samples. Saving objects preserves editability and allows the page to be rendered again. The input code splits very long strokes into additional objects before the validation limit, and requestAnimationFrame schedules preview drawing. Other users receive completed edits, rather than a guaranteed stream of every in-progress pen point.

Q10Canvas

How can a canvas object be selected, moved, or resized?

Reveal sample answer+

The application keeps object geometry outside the bitmap. Hit-testing checks those geometries, and the selection code uses bounding boxes for transforms. Dragging changes coordinates; resizing transforms the selected objects relative to the selection bounds. The resulting objects are submitted as versioned edits. A locked object is excluded from ordinary move and resize gestures.

Q11Canvas

What makes the tablet and stylus support work?

Reveal sample answer+

The editor uses Pointer Events, which expose the pointer type, pointer ID, and pressure when the hardware provides it. Pointer capture keeps an active gesture attached to the canvas. Only one active drawing gesture is tracked. Stylus-only mode makes touch input pan while a pen can draw; the companion link opens a compact view of the same workspace. Q12Canvas

How do multiple pages, templates, and presentation mode work?

Reveal sample answer+

A studio contains an ordered pages array, and each page has its own ID, name, background, and elements. Page actions add, copy, rename, reorder, or remove pages, with a limit of 20 and at least one page remaining. Templates insert ordinary editable objects. Presentation mode displays those same pages with navigation; it does not create a separate slide-file format. PNG export renders a page, while PDF output uses the browser print flow.

Q13Realtime

Walk me through exactly what happens when a user adds text.

Reveal sample answer+

The canvas text editor creates an object and commits it through BoardStudio. useStudio assigns an action ID, queues the action, and renders an optimistic version. It sends studio:action to the server. The server validates the action, serializes it with other edits for that workspace, saves the new state, broadcasts studio:changed, and acknowledges the result. The client reconciles its pending queue with the confirmed state.

Q14Realtime

How do separate workspaces avoid receiving each other’s edits?

Reveal sample answer+

Socket.IO rooms use the board ID. The server remembers which board the socket joined, and studio operations check that the workspace has been opened before accepting edits. A changed state is emitted only to that board’s room. In the studio protocol, io.to(room) includes the sender so it can reconcile confirmed state; this differs from the older element protocol, which usually excluded the sender.

Q15Realtime

What does someone who joins late see?

Reveal sample answer+

After joining the board room, the client requests studio:open. The store loads or retrieves the current studio document and returns its pages, objects, revision, and recent receipts. The new client reconstructs the page from that state. It does not depend on having watched all earlier socket events.

Q16Realtime

What happens if the network drops while I am editing?

Reveal sample answer+

Pending actions remain in an account-and-workspace-scoped queue and are persisted in localStorage when available. The UI can keep rendering optimistic edits from the loaded workspace. After reconnecting, the client rejoins, loads the server state, filters already-receipted actions, and sends the remaining queue. This is temporary offline edit recovery, not a guarantee that the entire site can be opened offline for the first time. The queue is limited to 100 pending actions.

Q17Realtime

How do you avoid drawing the same edit twice after a reconnect?

Reveal sample answer+

Each action has an ID. The server stores recent action IDs as receipts and returns a duplicate result instead of applying a matching action again. The client also removes pending actions whose IDs appear in confirmed state. The studio retains the most recent 128 receipts, so this is bounded replay protection, not an unlimited exactly-once guarantee for arbitrary old actions.

Q18Realtime

What if two users edit the same object at almost the same time?

Reveal sample answer+

Each object has a version, and an edit includes expectedVersion. The server serializes edits within that workspace in this Node process. The first valid edit increments the object version; a later edit using the old version is rejected and the client receives the current state. This prevents a silent overwrite, but it does not merge both people’s text. The project does not implement a CRDT or operational transformation.

Q19Realtime

Does “All changes saved” mean the database accepted the edit?

Reveal sample answer+

For studio actions, the server awaits the persistence save before acknowledging and broadcasting the new revision. If the save fails, it does not replace the confirmed cache with the proposed state. The client reports an error and reconciles with the available server state; rejected edits are not automatically retried forever. The older element protocol uses a different write-through mechanism, so I would scope this answer to the studio.

Q20Realtime

How does undo avoid erasing another person’s work?

Reveal sample answer+

The current tab keeps a local history of its object edits, including previous values and object versions. Undo produces a compensating versioned action instead of resetting the entire board to an old screenshot. If a relevant object’s version no longer matches the history entry, undo reports a conflict. This is session-local object-edit history, not permanent database history or a promise to undo every page-management action.

Q21Security

How are passwords stored and checked?

Reveal sample answer+

Passwords are hashed with Node’s scrypt using a random salt, not stored as plaintext or reversibly encrypted. The stored value includes the hashing parameters, salt, and derived key. Login derives a key for the submitted password and uses timingSafeEqual when lengths match. The server also bounds concurrent expensive password hashes and rate-limits account attempts.

Q22Security

Are you using JWTs? How do sessions and logout work?

Reveal sample answer+

This project uses opaque random session tokens rather than JWTs. The browser receives an HttpOnly cookie, Secure in production and SameSite=Lax by default. MongoDB stores a SHA-256 hash of the token with the user ID and a seven-day expiry. Logout deletes the session and disconnects its socket room. Replacing a session also disconnects the old session’s sockets, and an expiry timer closes connections that outlive the session.

Q25Security

How do you keep picture uploads from becoming unbounded or unsafe?

Reveal sample answer+

The browser accepts PNG, JPEG, or WebP, rejects very large input files, resizes the image, and uploads a compressed WebP. The server independently checks the MIME type and byte signature, rejects oversized payloads, and applies an upload-count limit per workspace. Image bytes live separately from vector state. SVG is not accepted. These checks are bounds and format validation, not a claim that malware scanning is implemented.

Q26Security

Which inputs are validated before an edit is saved?

Reveal sample answer+

The domain module validates supported object types, IDs, colors, numeric ranges, dimensions, point counts, and text length, and constructs a clean object from allowed fields. Workspace actions also enforce limits such as page count and total object count. The store bounds serialized vector state to 6 MB. Socket.IO limits single incoming messages to about 1 MB. Validation is enforced on the server, while matching client rules give earlier feedback.

Q27Deployment

Why serve the frontend and backend from one Azure origin?

Reveal sample answer+

Express serves the built Vite files, API routes, and Socket.IO from the same HTTPS website. This simplifies cookie-based authentication and avoids requiring cross-site cookies between unrelated frontend and API domains. The image API uses /api/assets, leaving Vite’s /assets path available for public JavaScript bundles. A route collision there was identified and covered by a regression test.

Q31Deployment

What would have to change before running several backend instances?

Reveal sample answer+

Rooms, presence, and per-workspace queues currently live in one server process. Merely adding instances could allow competing writes and inconsistent room broadcasts. I would add a shared Socket.IO adapter, design a distributed ordering or database concurrency strategy, and review session revocation and rate limits across instances. Sending full studio snapshots for each edit is also a bandwidth tradeoff worth replacing with smaller deltas at scale.
